# Skye example coverage: 26 new interface-validation scripts across 13 component areas

This task adds 26 standalone example scripts (plus the `examples/README.md` category index) so the owner can read the framework's public surface end to end before a dedicated spec is written. The scripts span `base`, `models`, `auth`, `store`, `tools`, `memory`, `guard`, `policy`, `observe`, `gateway`, `agents`, `teams` and `flows`. Each is a `main()`-style script that runs offline under `tests/examples` against the fake network with no optional/provider libraries installed. Where the public API already exists in `src` the example is "Live"; where it does not (memory stores, the gateway serve entry point, teams/flows orchestration, the ReAct loop) the example is "proposed-interface, guarded": it builds the intended call shape from real Ports and dataclasses, then returns before touching anything unimplemented.

Watch for: a ruff `I001` import-sorting error on a new path (`examples/agents/agent_with_hooks.py`) means the "ruff clean on new paths" acceptance criterion fails right now (confirmed). The error was introduced by an uncommitted tree-wide facade rewrite (`skye.base.interfaces.X` → `skye.interfaces`), not by this task's commits, but it is present on disk on a new path and must be resolved before this is clean.

**Verdict**: NEEDS_CHANGES

## High-level view

The committed deliverable is complete and healthy: 26 new scripts plus the README index, `uv run pytest tests/examples -q` is green at 139 passed, black is clean on all 13 new directories, and the committed sources (HEAD) are ruff-clean. The new files honor the project rules that matter here: dataclasses not pydantic for user shapes, no top-level import of any forbidden optional library, and no LangChain-style names.

The proposed-interface examples are correctly guarded. `agents/react_agent.py` wires `create_agent(REACT, ...)` but never calls `.invoke` (the only part that raises `NotImplementedError`); `agent_with_hooks.py` constructs the real `ReActAgent` placeholder and returns before any loop; gateway, teams and flows compose real `Runnable`/`AuthorizerInterface`/`CapabilityRegistry` parts and return before any not-yet-existing entry point. Memory examples satisfy `MemoryEntryLike` with a plain `@dataclass` and deliberately do not import the pydantic `MemoryEntry`.

The out-of-scope boundary holds for this task's commits: `examples/prompts/` and `examples/providers/router_example.py` are untouched across `origin/main..HEAD`, and the two pydantic structured-output example files were not modified by any FEAT commit.

The one gap is the ruff failure. The working tree carries an unrelated, uncommitted rewrite that collapsed four distinct `from skye.base.interfaces.<module> import ...` lines in `agent_with_hooks.py` into four `from skye.interfaces import ...` lines; ruff now wants them merged into one sorted block. The committed version of the same file passes ruff. The same uncommitted workstream also edited the pydantic structured-output files, so if that rewrite is meant to land it needs its own `ruff --fix` pass and a decision about the structured-output files; if it is not part of this task it should be reverted so the new paths verify clean.

### Ruff failure on a new path

`examples/agents/agent_with_hooks.py` fails `ruff check` with `I001`:

```
from skye.agents import REACT, create_agent
from skye.interfaces import MemoryEntryLike, MemoryInterface
from skye.interfaces import EventType, ObserverInterface
from skye.interfaces import Runnable
from skye.interfaces import SafetyFilterInterface, SafetyResult
```

The committed HEAD version of this file imported from four distinct modules (`skye.base.interfaces.memory`, `.observer`, `.runnable`, `.safety`), which ruff accepts as sorted; `uv run ruff check` on `git show HEAD:...` passes. The uncommitted rewrite replaced all four with `skye.interfaces`, producing four same-module lines ruff wants merged. The fix is mechanical (`ruff --fix`) but until it is applied the new-paths ruff gate is red. Black is clean on all 26 files.

### Proposed-interface examples stay clear of unimplemented APIs

The guarded examples are the risk area for "never invoke an unimplemented src API," and they hold up. `create_agent(REACT, ...)` is a real call that returns a `ReActAgent` whose `__init__` only stores options; the `NotImplementedError` lives solely in `ReActAgent.invoke`, which none of the agent examples call. `react_agent.py` shows the factory/model/tools wiring and returns; `agent_with_hooks.py` builds memory/guard/observe from real Ports, constructs the agent, asserts it is a `Runnable`, and returns before any loop. The gateway, teams and flows examples build from `CapabilityRegistry`, `AuthorizerInterface` and the `Runnable` Port and guard-return before any serve/orchestrate entry point. `flows/sequential_flow.py` demonstrates its deliberate cycle with a line containing `Expected`, so the harness does not treat it as a failure.

### Project-rule conformance of the new files

No new example imports a forbidden optional library (`openai`, `anthropic`, `boto3`, `numpy`, `redis`, `httpx`, `tiktoken`, `fastmcp`, `yaml`, ...) at module top level; optional backends and the fastmcp branch are constructed inside `try/except (ImportError, MissingExtraError)`. The two memory examples use a plain `@dataclass` satisfying `MemoryEntryLike` and explicitly do not import the pydantic `MemoryEntry`, matching D24 (dataclasses not pydantic). `examples/README.md` carries a category entry for every new directory with a Live / proposed-interface label, satisfying R24.1.

### Note on the fastmcp example

Per FEAT-003's recorded finding, `fastmcp` is actually installed in this environment, so `mcp_fastmcp.py` constructs the fastmcp client to prove the opt-in path but makes no network call through it (the fake network only patches `urllib.request.urlopen`, not fastmcp's httpx socket). The built-in MCP path is exercised live against the fake `/mcp` server. This keeps the script green and is the correct call under the harness.
