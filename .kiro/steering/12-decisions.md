# Decisions

The choices the owner has made (the log) and those not yet taken (open). Requirements cite them as "D13" or "open decision O7".
A decision is never rewritten: a later one supersedes it and the old one is marked "superseded by Dn". When an open decision is
taken, it moves to the log as the next D-number, the requirement it affects is edited in `10-requirements.md`, and its entry leaves
the open list.

- **O38** A `skye render` command that draws a `.skye` file as a Mermaid diagram, with the option `--stdout` to print it inline. Raised on 2026-11-07. The reason: an agent (or a person) that documents a flow, a router or a whole project in Markdown can run `skye render flow.skye --stdout` and paste a diagram that is always in step with the file, instead of drawing one by hand that drifts. It builds on D51 and D70, which put `to_mermaid()` in version 2 (the diagram is *generated* from the model; no Mermaid is ever parsed, as decided with D50), and D65 (`to_text` is the opposite direction). Sub-questions to take:
  1. **Whether to build it, and when.** Version 1 (it needs only the parsed `FlowSpec`/`RouterSpec`, which exist) or keep it in version 2 with `to_mermaid()` as D70 says; the question is whether the Markdown use case moves it forward.
  2. **The command.** `skye render FILE [--name NAME] [--stdout] [-o OUT] [--fence] [--direction TD|LR]`: with no option, write `FILE.mmd` next to the file (or `-o`); `--stdout` prints the diagram and writes nothing; `--fence` wraps the diagram in a ```mermaid fence so it can be pasted into a `.md` file as it is (and the default for `--stdout` when the output is a terminal or a pipe?). Which of these are really needed, what is the default, and whether one file with several blocks renders all of them (one diagram each, titled with the block name) or only the `--name` one.
  3. **What is drawn.** A flow: steps as boxes, `choice` as a diamond with the `when` text on its edges, `parallel` as a subgraph with its branches and the `join` rule, `next` as an arrow, `on_error` and `on_timeout` as dotted arrows, `max_visits` and `foreach` as a note on the node, `run = flow.x` as a link to another diagram, `end` as a terminal node.   5. **How it is checked.** There is no Mermaid library (D49): tests check the structure of the text (every step is a node, every `next` is an edge, labels are escaped, the diagram is deterministic) and the examples of the language page render to a stable text; the rendering to an image stays with the tool that shows the Markdown (GitHub, the dashboard, an editor).
  6. **The skill and the rules.** The command is part of the command line, so the skill must name it (`references/cli.md`, `references/python-api.md`; the coverage tests of the skill fail until it does, D64) and an eval should ask a model to document a flow in Markdown with the diagram.
