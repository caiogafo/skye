# Decisions

The choices the owner has made (the log) and those not yet taken (open). Requirements cite them as "D13" or "open decision O7".
A decision is never rewritten: a later one supersedes it and the old one is marked "superseded by Dn". When an open decision is
taken, it moves to the log as the next D-number, the requirement it affects is edited in `10-requirements.md`, and its entry leaves
the open list.

What is the minimal description a component must give to be exposed (name, description, input and output schema, streaming or not, authentication)?
  2. **One protocol-neutral layer or one adapter per protocol.** A single internal "served component" description (an `Endpoint`/`Service` dataclass with the schema and the call) from which each protocol is a thin adapter, or a separate server per protocol with its own code. The neutral layer is the way to keep MCP, A2A and HTTP from drifting apart.
  3. **What the standard library gives, per protocol.** The built-in level: a JSON-RPC 2.0 core (MCP over stdio and over streamable HTTP, `http.server`), an agent card and the A2A task methods (JSON over HTTP), and plain request and response handlers that take a dict and return a dict (the shape that AWS Lambda, API Gateway and any WSGI or ASGI wrapper need, so no web framework is required). Where does the built-in level stop (no WebSocket, no TLS, no concurrency beyond one invocation, as D27 asks) and what is left to a third-party stack?
  4. **The plug-and-play seam.** When the user wants a real stack, how is it plugged in without Skye importing it: an `Adapter` Port (`Protocol`, D37) that a user or an extra implements; an optional extra per stack (`mcp-server`, `a2a`, `asgi`), each importing its library lazily and declaring exactly that library (R7, R8); and the rule that the same component description works with the built-in server and with the third-party one, so switching is one line. Which stacks get a first-party extra (the MCP SDK, the A2A SDK, one ASGI framework) and which are left to the user?

  7. **Where it lives.** A new component (for example `serve`), the existing `gateway` (O19 asks whether it is still needed; this question may answer it), or `tools` and `agents` each with their own server code. The import rules (`flows` imports only `base`, D52; nothing imports another runtime component) decide which are possible.
